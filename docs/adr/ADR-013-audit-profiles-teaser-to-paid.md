# ADR-013. Профили аудита и переход из тизера в платный

Дата: 2026-09-11. Статус: принято.

## Контекст

Три набора параметров (тизер, стандарт $79, расширенный $199) должны управлять поведением шагов без условий в коде.

## Решение

`packages/config/audit-profiles.v1.json` — файл профилей. Аудит хранит `profile_id` и `profile_version`. Шаги читают объём работы из профиля через `StepContext`, не из условий.

Платный аудит — новый `audit_id` с `parent_audit_id`. Из тизера переиспользуются паспорт и категория (если тизеру < 14 дней). Краулер выполняется заново всегда.

## Причины

- Шаг не проверяет тип аудита — только профиль. Добавить тариф = добавить запись в файл
- `parent_audit_id` связывает тизер и платный аудит для аналитики
- Кэш категорий работает независимо от родства аудитов

## Последствия

Лимит «один тизер на домен в 30 дней» на платные аудиты не распространяется. Флаг `is_internal` исключает аудит из всех лимитов и бенчмарков.
