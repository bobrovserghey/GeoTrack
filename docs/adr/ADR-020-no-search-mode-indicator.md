# ADR-020 — Режим без поиска как индикатор вне скора

**Статус:** Принято  
**Дата:** 2026-09-24

## Контекст

AI-движки могут отвечать в двух режимах: с веб-поиском (движок активно ищет актуальную
информацию) и без поиска (ответ опирается только на параметры модели). Второй режим
показывает, насколько бренд «встроен в память» модели. Это ценная диагностика, но
сейчас нет достаточно данных для калиброванного включения в скор.

## Решение

Прогон без поиска выполняется в рамках платных профилей; его результат — индикатор
«знание без поиска» — отображается рядом со столпом A и управляет выбором находок
(в частности, нахождением разрыва «виден с поиском / не знают без поиска»), но
**не входит в скор столпа A и не влияет на общий балл** до следующей версии методологии.

## Причины

- Включение нового компонента в скор без калибровки создаёт несравнимые результаты
  между аудитами до и после включения.
- Индикатор полезен пользователю уже сейчас: он объясняет разницу между «движок меня
  знает» и «движок меня находит».
- Включение в скор — отдельное решение с eval, новая версия методологии и новый ADR.

## Последствия

- Режим передаётся адаптером движка: `search: false` в параметрах вызова API.
  Адаптеры, не поддерживающие режим, помечают результаты как `mode: 'search'` и
  не участвуют в прогоне без поиска для данного профиля.
- Ключ кэша включает поле `mode`: ответы `search` и `no_search` хранятся раздельно.
- `promptsWithoutSearch` в профиле задаёт число промптов; `noSearchEngines` —
  движки, участвующие в прогоне.
- Добавление в скор требует: eval на золотом наборе, обновления
  `methodology.v1.json` → новая версия, нового ADR.
