# ADR-021 — Клиентский слой промптов и персоны запроса в таксономии

**Статус:** Принято  
**Дата:** 2026-09-24

## Контекст

Категорийные промпты отражают вопросы среднего покупателя категории. Но реальный
покупатель конкретного бизнеса может формулировать иначе — через FAQ, отзывы,
сравнения с прямыми конкурентами. Без этого слоя отчёт говорит «вас не знают в
вашей категории», но не говорит «вас не знают по вашим собственным вопросам».
Одновременно разные персоны (например, «малый бизнес» против «enterprise-покупатель»)
задают разные вопросы; без персонной разметки невозможно дать срез «вас знают не той
аудитории».

## Решение

В платных профилях добавляется шаг `prompts.client`, который собирает формулировки
из трёх источников — вопросы клиента со страницы тизера, контент сайта, сниппеты
SerpAPI — и превращает их в промпты на языке локали. Параллельно в таксономии
каждой категории фиксируются две-три персоны запроса; треть discovery- и
problem-led-промптов несёт `persona_id`; `category.detect` выбирает целевую персону
клиента по паспорту.

## Причины

- Клиентские промпты дают срез «клиентский vs категорийный» — один из четырёх
  срезов отчёта (§7.4 техплана); без них срез недоступен.
- Персоны в таксономии (не на сайте клиента) сохраняют кэшируемость промптов:
  промпт с `persona_id` остаётся общекатегорийным.
- Клиентские промпты никогда не кэшируются — они персональны по определению
  и стоят дёшево (несколько вызовов модели).

## Последствия

- В `packages/config/src/taxonomy.v1.json` в каждую категорию добавляется поле
  `personas: [{ id, label }]`, список из двух-трёх записей; изменение через
  новую версию файла или ADR.
- Клиентские промпты помечаются `cacheable: false`; попытка положить их в кэш —
  тест-запрет.
- Источник каждого клиентского промпта сохраняется (`source: 'client_input' |
  'site_content' | 'serp_snippet' | 'model_fallback'`); при fallback промпт
  помечается в отчёте как «модельный».
- `prompts.client` добавляется 15-м шагом пайплайна; зависит от шагов
  `passport`, `category.detect` и `competitors.detect`.
- `serpApiRequestsClient` в профиле задаёт число SerpAPI-запросов для этого шага.
