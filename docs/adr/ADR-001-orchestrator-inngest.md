# ADR-001. Оркестратор Inngest и условия перехода на Temporal

Дата: 2026-09-11. Статус: принято.

## Контекст

Нужен оркестратор для управления долгоживущими шагами аудита с идемпотентностью, ожиданиями и повторами.

## Решение

Использовать Inngest в фазе 1–2; интерфейс оркестратора изолирован так, чтобы переход на Temporal не расползался по коду шагов.

## Причины

- Managed-сервис, не требует Kubernetes
- Нативная поддержка `step.waitForEvent` для ожиданий категории и email
- Локальная разработка без внешних ключей через Inngest Dev Server

## Последствия

Шаги не зависят от Inngest напрямую — только через тонкий интерфейс. При переходе на Temporal в фазе 3 меняется адаптер, а не шаги.
