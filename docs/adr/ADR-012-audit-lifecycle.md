# ADR-012. Жизненный цикл аудита и таблица переходов статусов

Дата: 2026-09-11. Статус: принято.

## Контекст

Аудит — долгоживущий процесс с ожиданиями, сбоями и ручными действиями. Состояние должно быть предсказуемым.

## Решение

Состояние в `audits.status`. Единственная функция `transition(status, event)` в `core` с табличным описанием разрешённых переходов. Оркестратор и API вызывают только её.

Статусы: `queued → running → waiting_category → running → waiting_email → running → completed → in_review → delivered`. Плюс `needs_attention`, `failed`, `cancelled`.

## Причины

- Табличный автомат тестируется до кода
- Любой несанкционированный переход ловится тестом
- Экран прогресса рисует состояние из статуса, а не из последнего события

## Последствия

Ожидания реализуются через `step.waitForEvent` с таймаутом. Зависание `running` без событий 15 минут → `needs_attention` (платный) или `failed` (тизер).
