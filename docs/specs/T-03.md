# T-03. Контракты: Step, StepContext, StepResult, ArtifactRef, UsageRecord, реестр движков, профили аудита

**Зависит от:** T-02  
**Критерий приёмки:** типы экспортируются из core, тест на идемпотентный ключ, тест на чтение профиля

## Что реализуется

### packages/core/src/contracts/

- `ArtifactRef` — ссылка на артефакт в Storage (key, bucket, sizeBytes, hash, mimeType)
- `UsageRecord` — запись о вызове провайдера (provider, model, tokensIn, tokensOut, costUsd)
- `StepResult<T>` — результат шага: status ok|partial|failed, data, artifacts, usage, notes
- `Step<I, O>` — тип функции шага
- `StepContext` — контекст: auditId, idempotencyKey, profile, budget, logger, emit
- `Logger` — минимальный интерфейс логгера
- `EngineAdapter`, `EngineAnswer`, `EngineId`, `AskOptions` — контракт адаптера движка

### packages/core/src/

- `idempotency.ts` — `makeStepKey({ auditId, stepName, stepVersion })` → `"auditId:stepName:stepVersion"`

### packages/config/

- `audit-profiles.v1.json` — три профиля: teaser, standard, extended (все поля из §4.7)
- `engines.v1.json` — реестр движков: perplexity, chatgpt, gemini
- Zod-схемы для обоих файлов
- `getAuditProfile(id)`, `getEngineRegistry()` — синхронные читатели с валидацией

## Тесты

- `idempotencyKey` детерминирован, разные входы → разные ключи
- `getAuditProfile('teaser')` возвращает корректный профиль
- Все три профиля присутствуют и проходят схему
- `getAuditProfile('unknown')` бросает ошибку
- Реестр содержит три движка с обязательными полями
