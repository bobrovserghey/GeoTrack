# T-37 — Столп E: доступность (E2) и барьеры (E3)

## Статус

В разработке

## Зависимости

- T-08b (фабрика контекстов Playwright — сетевой слой, который реализует `CheckPageFn` в проде)

## Зачем

Шаг `collectAccessibilityCheck` собирает факты для двух критериев столпа E:

- **E2 — Семантика и доступность (20 баллов)**: автоматический аудит ключевых страниц через axe-core; нарушения доступности по уровню impact (critical / serious / moderate / minor)
- **E3 — Отсутствие барьеров для агентов (15 баллов)**: капча, антибот-стены, контент только после JS, блокирующие попапы

Scoring (E2 + E3) будет добавлен в T-40 вместе с остальными столпами E и D.

Тизерный профиль не включает столп E; шаг не вызывается.

## Вход

```ts
type AccessibilityCheckInput = {
  keyPages: string[];  // ключевые страницы из краулера
  origin: string;      // origin сайта ("https://example.com"), для E3
};
```

`keyPages` приходит из краулера и шагом не доверяется по длине: шаг сам режет список
до `MAX_KEY_PAGES = 10` (защитный верхний предел — каждая страница это отдельный прогон
браузера с axe). Факт усечения попадает в `notes` (см. «Алгоритм»).

> **Открытый вопрос продакта.** `tech-check` для B2 ограничивается 5 ключевыми
> страницами (`tech-check.ts:107`), для B4/B5 — 10 (`:240`, `:289`). Здесь выбрано 10.
> Единое значение (5 или 10) для всех шагов не зафиксировано — решение за продактом.

## Зависимости шага

```ts
type CheckPageFn = (url: string) => Promise<PageCheckResult>;

type AccessibilityCheckDeps = {
  checkPage: CheckPageFn;
};
```

`CheckPageFn` — единственный сетевой примитив шага. В проде реализуется фабрикой Playwright (T-08b) + `axe-playwright`. В тестах — заглушка.

## PageCheckResult (контракт `CheckPageFn`)

```ts
type PageCheckResult = {
  url: string;
  axeViolations: RawAxeViolation[];
  hasCaptcha: boolean;
  captchaType: string | null;    // 'recaptcha' | 'hcaptcha' | 'turnstile' | 'cloudflare' | 'unknown' | null
  hasBlockingPopup: boolean;
  rawHtml: string;               // HTML ДО выполнения JS (ответ сервера); шаг берёт из него видимый текст (extractText)
  renderedTextLength: number;    // длина innerText после рендеринга
  statusCode: number;            // HTTP-статус landing-страницы
};

type RawAxeViolation = {
  id: string;
  impact: 'critical' | 'serious' | 'moderate' | 'minor';
  description: string;
  nodeCount: number;
};
```

## Выход

```ts
// packages/core/src/steps/accessibility-check.ts

type AxeViolation = {
  id: string;
  impact: 'critical' | 'serious' | 'moderate' | 'minor';
  description: string;
  nodeCount: number;  // суммарно по всем проверенным страницам
};

type E2AccessibilityFacts = {
  measured: boolean;
  pagesAudited: number;
  criticalCount: number;
  seriousCount: number;
  moderateCount: number;
  minorCount: number;
  violations: AxeViolation[];  // дедуплицированы по id, nodeCount просуммирован
};

type E3BarrierFacts = {
  measured: boolean;
  captchaDetected: boolean;
  captchaType: string | null;
  antibotWallDetected: boolean;   // statusCode 403 или 429 на origin
  jsOnlyContent: boolean;         // renderedTextLength > видимый текст rawHtml * 3 (и >= 500 символов)
  blockingPopupDetected: boolean;
};

type AccessibilityCheckOutput = {
  e2: E2AccessibilityFacts;
  e3: E3BarrierFacts;
};
```

## Алгоритм

### E2 — доступность

0. Урезать `keyPages` до `MAX_KEY_PAGES = 10`. Если входных страниц было больше —
   добавить в `notes` запись `keyPagesTruncated:<было>→<стало>`. Усечение — проектный
   лимит, а не отказ измерения, поэтому на статус шага оно не влияет: `partial`
   означает «не удалось проверить», а не «проверено меньше, чем пришло».
1. Для каждой страницы из урезанного `keyPages` вызвать `checkPage(url)`.
2. Если все вызовы бросили исключение → `e2.measured = false`.
3. Собрать нарушения со всех успешных страниц:
   - Дедуплицировать по `violation.id`.
   - Для каждого уникального id суммировать `nodeCount` по страницам.
4. Посчитать `criticalCount`, `seriousCount`, `moderateCount`, `minorCount` — сумма `nodeCount` по violations соответствующего impact.
5. `pagesAudited` — количество страниц, по которым не было исключения.

### E3 — барьеры

1. Вызвать `checkPage(origin)`.
2. Если вызов бросил исключение → `e3.measured = false`.
3. Определить флаги:
   - `captchaDetected` = `result.hasCaptcha`
   - `captchaType` = `result.captchaType`
   - `antibotWallDetected` = `result.statusCode === 403 || result.statusCode === 429`
   - `jsOnlyContent` = `renderedTextLength >= 500 && renderedTextLength > extractText(rawHtml).length * 3` (сравнение с видимым текстом сырого HTML, а не с размером разметки)
   - `blockingPopupDetected` = `result.hasBlockingPopup`

`rawHtml` — это именно пре-JS HTML (ответ сервера). Сериализация DOM после работы JS
на этом входе непригодна: эвристика сравнивала бы рендер с самим собой. Откуда брать
пре-JS HTML — вопрос реализации `checkPage` (T-79).

`rawHtml` недоверенный и ничем не ограничен по размеру, поэтому у разбора есть верхний
предел `MAX_RAW_HTML_CHARS = 8 * 1024 * 1024`. **Усекать вход префиксом нельзя:**
отрезанный хвост с настоящим текстом даёт видимый текст 0, условие вырождается в
`renderedTextLength >= 500` и флаг ставится почти всегда (реальный случай —
server-rendered страница на 2.2 МБ с гидратационным JSON на 2.19 МБ в `<head>` и
40 000 символов текста в `<body>`: на полном HTML `false`, на префиксе 2 МБ `true`).
Поэтому при превышении лимита вердикт **не выносится**: `jsOnlyContent = false`, а факт
уходит в `notes` записью `jsOnlyContentSkipped:rawHtml <длина> > <лимит>` (как
`keyPagesTruncated`, на статус шага не влияет). Значение 8 МБ выбрано по замерам
линейного `extractText` (2/8/16 МБ: обычная разметка 17/92/169 мс, незакрытые
`script`/`style` 0.5/2/4 мс, вырожденный поток «<>» 106/585/1061 мс) — дёшево по CPU
даже в худшем случае и с запасом покрывает реальные страницы с гидратационным JSON.

Шаг возвращает `StepResult<AccessibilityCheckOutput>` со статусом `ok` в норме, `partial` если некоторые страницы E2 не удалось проверить, `failed` если оба (`e2.measured` и `e3.measured`) равны false.

## Артефакты

## Тесты

Нумерация ниже — исходный минимальный набор спеки; в файлах тестов больше
(30 в `accessibility-check.test.ts` + 26 в `html-text.test.ts`): добавлены случаи
JS-only детекции (SPA-оболочка, инлайн-скрипты, комментарии, `<template>`, лимит
`MAX_RAW_HTML_CHARS`, не-ASCII заглавные буквы), фиксация лимитов в `notes` и
линейность `extractText` на недоверенном HTML.

### E2 — доступность (8 тестов)

1. **Все страницы успешны — violations агрегируются**: 2 страницы, на каждой `id: 'color-contrast'` с `nodeCount: 3` → итого `nodeCount: 6`
2. **Дедупликация по id, nodeCount суммируется**: 2 страницы с разными violations + одним общим
3. **criticalCount / seriousCount / moderateCount / minorCount корректны**
4. **Пустой keyPages → measured: false**
5. **Все вызовы бросают исключение → measured: false**
6. **Частичный отказ — часть страниц успешна**: 1 из 2 бросает → `pagesAudited: 1`, measured: true
7. **Нет violations → все счётчики 0, measured: true**
8. **`keyPages` урезан до 10**: 15 входных страниц → `pagesAudited: 10`, статус `ok`

### E3 — барьеры (19 тестов)

9. **Нет барьеров → все флаги false, measured: true**
10. **Капча обнаружена**: `hasCaptcha: true`, `captchaType: 'recaptcha'`
11. **Антибот-стена**: `statusCode: 403` → `antibotWallDetected: true`
12. **JS-only контент**: видимый текст `rawHtml` 2000, `renderedTextLength: 6001` → `jsOnlyContent: true`
13. **Граничный случай JS-only**: видимый текст `rawHtml` 2000, `renderedTextLength: 6000` → false (не строго больше)
14. **SPA-оболочка**: ~3 КБ разметки почти без видимого текста, рендер 6000 → true
15. **SSR-страница**: видимый текст ≈ рендер → false
16. **Большой инлайн-скрипт без прироста от JS** → false
17. **Большой инлайн-скрипт не считается видимым текстом**: 400 видимых + 50 КБ скрипта, рендер 3000 → true
18. **Ниже пола по длине рендера** (< 500 символов) → false
19. **Незакрытый `<script>` с большим телом JS** не считается видимым текстом → true
20. **`</script >` с пробелом** распознаётся как закрывающий тег → true
21. **Комментарий с «>» внутри** не утекает в видимый текст → true
22. **Содержимое `<template>`** инертно и не считается видимым текстом → true
23. **`İ` (U+0130) в `rawHtml`** не искажает вердикт: SSR-страница остаётся false
24. **HTML больше `MAX_RAW_HTML_CHARS`**: вердикт не выносится → false + запись `jsOnlyContentSkipped:` в `notes`, статус `ok`
25. **HTML в пределах лимита**: вердикт выносится, записи в `notes` нет
26. **SSR-страница 2.2 МБ с гидратационным JSON в `<head>`** → false (прежнее усечение до 2 МБ давало ложный true)
27. **checkPage бросает исключение → e3.measured: false**

### Интеграционные (3 теста)

28. **E2 и E3 измеряются независимо**: E2 keyPages пусты (→ не измерено), но origin доступен (→ E3 измерено)
29. **Усечение `keyPages` фиксируется в `notes`**: 15 страниц → `keyPagesTruncated:15→10`, статус `ok`
30. **Без усечения** записи `keyPagesTruncated` в `notes` нет

### `extractText` — `html-text.test.ts` (26 тестов)

- Корректный HTML: снятие тегов/`script`/`style`, склейка без лишнего пробела, регистр тегов, `noscript` считается видимым текстом
- Не-ASCII заглавные буквы: `İ` (U+0130) — единственный код-пойнт, который `toLowerCase()` удлиняет (`i` + U+0307), поэтому разбор идёт прямо по `html` без параллельной строки в нижнем регистре; иначе индексы и срезы расходятся
- Незакрытые `script`/`style` съедают остаток документа; закрывающий тег с пробелом (`</script >`, `</style >`)
- Самозакрывающаяся форма (`<script/>`, `<style/>`, `<template/>`) снимается как обычный тег и остаток документа **не** съедает: обнуление видимого текста дало бы ложный `jsOnlyContent: true`
- Комментарии вырезаются целиком (в том числе с «>» внутри и незакрытые); `<!-->` и `<!--->` — завершённые комментарии по HTML5 (abrupt closing of empty comment); содержимое `<template>` инертно
- Производительность на недоверенном HTML: 1–2 МБ с десятками тысяч незакрытых `<script`/`<style`, хвост из «<» без «>», 2 МБ обычной разметки, 2 МБ текста с `İ` — каждый случай < 1000 мс (прежние ленивые регулярки давали O(n²): ~9 с на 1 МБ)
