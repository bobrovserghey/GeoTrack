## Изменения API

### POST /api/audits (расширение)

Тело запроса:
```ts
{ url: string; turnstileToken: string; category?: string; competitors?: string }
```

Ответ `201`:
```json
{ "auditId": "<uuid>", "progressToken": "<raw_url_safe_token>" }
```

- Генерирует прогресс-токен: `generateProgressToken()` → `{ token, hash }`
- Сохраняет hash в `report_tokens` с `tokenType='progress'`, `expiresAt = now + 7 дней`
- Передаёт `categoryHint` и `competitors[]` в Inngest event payload
- Лендинг редиректит на `/report/{auditId}?pt={progressToken}`

### POST /api/audits/[auditId]/category

Тело запроса:
```ts
{ progressToken: string; categoryId: string }
```

- Валидирует progressToken через `report_tokens`
- Отправляет Inngest-событие `geotrack/audit.category.selected` с `{ auditId, categoryId }`
- Ответ `204`

### GET /api/audits/[auditId]/candidates

Query: `?pt=<progressToken>`

- Валидирует token
- Читает `categories` table для этого auditId
- Возвращает `{ candidates: { slug, name, confidence }[] }` — до 3, отсортированных по confidence

### GET /api/taxonomy

- Возвращает `{ categories: { id, name }[] }` — полная таксономия из `getTaxonomy()`

## Изменения воркера

### audit-run-handler.ts

Новая сигнатура:
```ts
async function auditRunHandler(
  auditId: string,
  step: StepTools,
  deps: AuditRunDeps,
  categoryHint?: string,
): Promise<void>
```

Поведение:
- Если `categoryHint` задан → шаги `status.waiting-category` и `waitForEvent` пропускаются; вместо них — `category.preset` (записывает событие `category.preset` и продолжает пайплайн)
- Если `categoryHint` не задан → поведение не меняется (существующие тесты проходят)

Step-последовательность с `categoryHint`:
```
status.running → crawl.stub → category.preset → engine-poll.stub → status.completed
```

Step-последовательность без `categoryHint` (без изменений):
```
status.running → crawl.stub → status.waiting-category → [waitForEvent 10m] → status.running-after-category → engine-poll.stub → status.completed
```

## S2 — Экран прогресса (audit-progress.tsx)

Компонент «use client», порт дизайна S2_S3_Audit_Progress.html 1:1.

Props:
```ts
{ domain: string; auditId: string; progressToken: string | null }
```

Поведение:
- Опрашивает `GET /api/progress?token=...&after_seq=...` раз в 2 с
- Если `progressToken === null` → показывает загрузчик без опроса
- Если `isTerminal && READY_STATUSES.has(status)` → `router.replace('/report/{auditId}')`
- При `status === 'waiting_category'` → показывает S3-модал (только если пользователь не кликнул «None of these»)
- Прогресс-бар: queued=5%, running=25%, waiting_category=50%, completed=100%

### Столбцы

**Левый (Pillars):** 5 строк — Answer Visibility (A), AI Crawlability (B), Content Citability (C), Entity & Authority (D), Agent-Readiness (E).

Статус иконки:
- Первый pillar: spinner-SVG, если status = `running`; иначе dashed-circle
- Остальные: всегда dashed-circle

**Правый:** Live feed (события из progress API) + email notification block

### Маппинг событий → текст ленты

| eventType          | payload         | Текст                                    |
|--------------------|-----------------|------------------------------------------|
| status.changed     | to: running     | Audit started                            |
| status.changed     | to: waiting_category | Waiting for category selection      |
| status.changed     | to: running, после category | Pipeline resumed             |
| status.changed     | to: completed   | Analysis complete                        |
| step.started       | step: crawl.stub | Crawling site…                          |
| step.completed     | step: crawl.stub | Site crawl done                         |
| step.started       | step: engine-poll.stub | Querying AI engines…             |
| step.completed     | step: engine-poll.stub | AI engine data collected        |

## S3 — Окно категории

Overlay (fixed, z-index 40), показывается при `status === 'waiting_category'` и `!noneSelected`.

- Загружает кандидатов: `GET /api/audits/{auditId}/candidates?pt=...`
- Показывает до 3 карточек-кнопок (name + description)
- Поиск: при вводе запрашивает `GET /api/taxonomy`, фильтрует локально
- «None of these» → `setNoneSelected(true)` (модал скрывается, timeout продолжается)
- «Continue» (активна при выбранном categoryId) → `POST /api/audits/{auditId}/category` → `setShowModal(false)`

## Лендинг (page.tsx)

- Добавить state `category` и `competitors`
- Подключить к существующим `<input>` в аккордеоне
- `handleSubmit` отправляет `{ url, turnstileToken, category?, competitors? }`
- Ответ включает `{ auditId, progressToken }`
- Редирект: `window.location.href = /report/${auditId}?pt=${progressToken}`

## Acceptance criteria

- [ ] Открытие `/report/{auditId}?pt=...` при неготовом статусе показывает S2
- [ ] S2 обновляется каждые 2 с без перезагрузки
- [ ] Live feed накапливает события без дублей и без пропусков
- [ ] При `status = waiting_category` появляется S3-модал
- [ ] S3 нельзя закрыть крестиком; выходы только «Continue» и «None of these»
- [ ] «Continue» с выбранным кандидатом отправляет событие и скрывает модал
- [ ] «None of these» скрывает модал без отправки события
- [ ] Если категория задана на лендинге, `waiting_category` не наступает, S3 не показывается
- [ ] При достижении `completed`/`in_review`/`delivered` — редирект на `/report/{auditId}` (без `?pt`)
- [ ] Поля category/competitors на лендинге отправляются в POST /api/audits
- [ ] CI зелёный
