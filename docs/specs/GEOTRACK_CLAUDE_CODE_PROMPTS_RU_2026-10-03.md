# GeoTrack — промпты для Claude Code по итогам ревью

Дата: 2026-10-03. Версия 1.0. Основание: `docs/specs/GEOTRACK_REVIEW_DECISIONS_RU_2026-10-03.md` (далее — реестр).

## Резюме

Тринадцать задач в порядке выполнения. Каждый промпт копируется целиком. Перед первой задачей реестр решений нужно положить в `docs/specs/` репозитория: промпты ссылаются на него по номерам решений.

**Ключевые предположения**

- Одна задача — один PR, слияние после зелёного CI.
- Экран, для которого нет утверждённого макета, не строится: задача делает логику и API.
- Задачи 2, 6 и 10 не зависят от остальных и могут идти в любой момент.

**Рекомендация:** начать с задач 1 и 2, затем идти по номерам.

**Статус:** готово к использованию.

## 0. Общий блок правил

Вставляется в начало каждого промпта.

```text
Общие правила задачи:
1. Прочитай CLAUDE.md и docs/specs/GEOTRACK_REVIEW_DECISIONS_RU_2026-10-03.md.
   Решения продакта в реестре окончательны; номера Р-NN и П-N — оттуда.
2. Сначала покажи план: файлы, миграции, тесты, ADR. Код — после моего
   подтверждения.
3. Детерминированное ядро: тесты до кода. Существующие тесты не удалять
   и не отключать.
4. Изменение инварианта оформляй ADR в docs/adr со статусом «предложено».
5. Новый экран или элемент интерфейса без утверждённого макета не строй:
   сделай логику и API, в описании PR перечисли, какого макета не хватает.
6. Ничего не утверждай о коде без проверки по репозиторию. Если реестр
   расходится с кодом так, что решение невыполнимо, остановись и спроси.
7. Один PR по шаблону из приложения Ж техплана.
```
