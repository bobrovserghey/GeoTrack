# T-44: PDF-версия платного отчёта (внутренний рендер-роут)

## Цель

1. Платный отчёт можно сгенерировать в PDF для скачивания/пересылки — без
   изменения основного веб-отчёта и без обхода токен-гейта (ADR-006).
2. PDF-вёрстка — порт эталонного дизайна `Report_Print.html` из
   `Geotrack_UI.zip` (правило 1:1), а не производная веб-отчёта
   (`report-content.tsx`): это отдельный, специально спроектированный для
   печати макет (постраничная A4-разбивка, один пример находки на пилар, без
   интерактивного «хрома»).
3. Ошибка генерации PDF не блокирует доставку веб-отчёта (жёсткое требование
   из техплана).

## Зависимости

- ADR-006 (модель доступа к отчёту) — PDF не должен ослаблять токен-гейт
- ADR-015 (фабрика контекстов Playwright, SSRF-защита для внешних сайтов)
- T-41 (находки), T-43 (токен-гейт платного отчёта, `confidenceLow/High` в `scores`)
- Обнаружено в ходе задачи: `S6_Full_Audit_Report.html` — отдельный, гораздо
  больший интерактивный веб-дизайн платного отчёта (сайдбар, корзина находок,
  фильтруемое приложение). Явно вне рамок T-44 — отдельная будущая задача.

## Решения (согласованы с продактом)

- **Отдельный внутренний роут, не flag на существующем отчёте.** Изначальный
  подход («добавить `pdfMode` в `report-content.tsx`») отменён после того, как
  обнаружился настоящий эталонный print-дизайн: `Report_Print.html` — не
  урезанная копия веб-отчёта, а самостоятельная печатная раскладка. Новый роут
  `apps/web/src/app/internal/report-render/[auditId]` рендерит отдельный
  компонент `ReportPdfContent`, который Playwright открывает и печатает в PDF.
- **Доступ к внутреннему роуту — сервисный ключ, не report-токен.** Роут вызывает
  только воркер (Playwright), не браузер пользователя; токен из ADR-006 тут
  неприменим. Новый `AUDIT_SERVICE_KEY` / заголовок `x-service-key`
  (`apps/web/src/lib/service-auth.ts`, `isValidServiceKey`) — тот же паттерн,
  что уже был у `apps/web/src/app/api/audits/route.ts` (T-26), вынесен в общий
  хелпер и переиспользован в обоих местах.
- **Отдельная Playwright-фабрика для внутреннего рендера (ADR-025), не
  переиспользование `createAuditContext`.** `createAuditContext` —
  SSRF-хардened для произвольных внешних сайтов (DNS-резолв + `isBlockedIp`);
  цель внутреннего рендера всегда одна и та же, код-сконструированная, доверенная
  страница — резолвить и блокировать по IP нечего. Новая
  `createInternalRenderContext` (`apps/worker/src/browser/internal-render-factory.ts`)
  переиспользует только `shouldBlockRequest` (схема/порт/тип ресурса) —
  инвариант не нарушен, добавлен второй разрешённый entry point для импорта
  `playwright` в `eslint.config.mjs` (по аналогии с `playwright-factory.ts`).
- **Упрощения макета относительно `Report_Print.html` — зафиксированы как
  сознательные, а не придуманы агентом:**
  - Единая таблица «Fix plan» вместо разбивки Quick wins / Strategic —
    `findings.effort` в схеме БД — свободный текстовый лейбл
    (`varchar(16)`, например «45 min · DevOps»), не число часов; бакетировать
    не по чему без привязки по hours-порогу, которого в данных нет.
  - Блок «What capped your score» из дизайна не включён — данные о применённых
    блокерах (`score.compute`) нигде не персистятся (пакет `core` возвращает их
    только в памяти); `cappedPillarNotes` сейчас всегда `[]`.
  - `citationsPct` в таблице конкурентов — всегда `null`: в пайплайне нет
    отдельного сигнала «процитировано» отдельно от «упомянуто».
  - Это не правки дизайна (цвета/шрифты/структура не менялись) — это честное
    отображение отсутствующих данных вместо выдумывания значений.
- **PDF-механика реальна, данные — реальные DB-запросы, но пайплайн, который бы
  их туда писал, частично не существует.** Напоминание из CLAUDE.md:
  ни один адаптер движка не вызывается в `apps/worker` с реальным ключом,
  `score.compute`/`findings.build` не пишут в `scores`/`findings`/`mentions`
  (подтверждено: `insert(findings/scores/mentions)` нигде не встречается). Роут
  в `page.tsx` честно читает то, что в таблицах реально может быть — вплоть до
  того дня, когда будет настоящий прогон.

## Файл 1: `apps/web/src/lib/service-auth.ts`

```ts
export function isValidServiceKey(headers: Headers): boolean {
  const serviceKey = process.env.AUDIT_SERVICE_KEY;
  if (!serviceKey) return false;
  return headers.get('x-service-key') === serviceKey;
}
```

`apps/web/src/app/api/audits/route.ts` — локальная `validateServiceKey` удалена,
используется этот общий хелпер.

## Файл 2: `apps/web/next.config.ts`

Второй блок заголовков для `/internal/:path*` — тот же noindex/no-referrer, что
и у `/report/:path*` (роут не предназначен для публичного доступа).

## Файл 3: `apps/web/src/app/internal/report-render/[auditId]/report-pdf-content.tsx`

Порт `Report_Print.html` 1:1: обложка (лого, домен, общий балл, band-лейбл,
дата + версия методологии), Overview (балл + интервал + медиана категории,
опциональный блок предупреждений), опциональная таблица «You vs competitors»,
«Pillar detail» по каждому из 5 пиларов (заголовок + саммари + пример находки +
строка «Passed checks»), единая таблица «Fix plan», «Appendix: prompts &
answers». CSS через инлайн-стили на уже существующих глобальных переменных
(`var(--text-primary)`, `var(--band-*-fg)`, `var(--severity-*)` и т.д. из
`globals.css`) — новых токенов не вводилось.

## Файл 4: `apps/web/src/app/internal/report-render/[auditId]/page.tsx`

Серверный компонент-загрузчик данных:

- Гейт: `isValidServiceKey(await headers())` → `notFound()`.
- `scores` — читает `confidenceLow`/`confidenceHigh` для интервала скора.
- `findings`/`techChecks` — группировка по пилару через первую букву
  `criterionKey`/`criterion` (`A`–`E`).
- `mentions` + `engineRuns` — агрегация по бренду для таблицы конкурентов
  (`mentionsPct = количество различных engine_run_id / totalEngineRuns` —
  уникальности `(engine_run_id, brand)` в схеме нет, поэтому счёт строк давал
  бы >100%; `avgPosition` — среднее непустых позиций).
- `engineRuns` + `prompts` + `mentions` — до 20 строк для приложения
  «prompts & answers» (`prompts.promptType`, колонка БД `prompt_type`),
  один `leftJoin` на `prompts` плюс один `inArray`-запрос по `mentions`
  (не запрос на строку) и обязательный `orderBy` — `limit` без сортировки не
  детерминирован и ломал бы идемпотентность шага.
- Все обращения к БД обёрнуты: любая ошибка (например, не-UUID `auditId` →
  `invalid input syntax for type uuid`) деградирует в `notFound()`, а не в 500 —
  тот же паттерн, что на странице отчёта T-43. `notFound()` вызывается только
  вне `try`, чтобы его управляющее исключение (`NEXT_NOT_FOUND`) не было
  проглочено.

## Файл 5: `apps/worker/src/browser/internal-render-factory.ts`

```ts
export async function createInternalRenderContext(
  options: { serviceKey: string },
): Promise<BrowserContext> {
  const browser = await chromium.launch({ headless: true });
  const context = await browser.newContext({
    javaScriptEnabled: true,
    extraHTTPHeaders: { 'x-service-key': options.serviceKey },
  });
  await context.route('**/*', async (route) => {
    const decision = shouldBlockRequest(route.request().url(), route.request().resourceType());
    if (decision.blocked) { await route.abort('blockedbyclient'); return; }
    await route.continue();
  });
  return context;
}
```

Всё после `chromium.launch()` — внутри `try/catch`, который закрывает браузер
перед пробросом ошибки: наружу отдаётся только `BrowserContext`, поэтому при
сбое `newContext()`/`route()` вызывающий код не получил бы хендла и процесс
Chromium утекал бы на каждый сбой.

Переэкспортирует `type { BrowserContext }` из `playwright` — второй (после
`playwright-factory.ts`) разрешённый импорт `playwright` в `eslint.config.mjs`
(ADR-015/ADR-025), чтобы потребители (`report-pdf.ts`) не импортировали
`playwright` напрямую.

## Файл 6: `apps/worker/src/storage/types.ts`

export type StorageClient = {

## Файл 7: `apps/worker/src/steps/report-pdf.ts`

```ts
export async function generateReportPdf(
  input: { auditId: string; domain: string },
  deps: { baseUrl: string; serviceKey: string; storage: StorageClient; createRenderContext?: RenderContextFactory },
): Promise<StepResult<{ pdfArtifact: ArtifactRef | null }>>
```

- Открывает `createInternalRenderContext({ serviceKey })`, переходит на
  `{baseUrl}/internal/report-render/{auditId}`, вызывает `page.pdf()`.
- Футер — 1:1 с `Report_Print.html` (`doc-page` slot `footer`): слева
  «Geotrack · AI Visibility Audit · {domain}», справа «Confidential»,
  9px, `var(--font-mono)`/`var(--text-tertiary)` (инлайнены литералами —
  Playwright рендерит `footerTemplate` в изолированном документе без доступа
  к стилям приложения). Поля — 18mm со всех сторон, как у `doc-page`.
- Загружает буфер через `deps.storage.upload(...)`, возвращает `ArtifactRef`
  и в `data.pdfArtifact`, и в `artifacts`.
- **Все ошибки (навигация, рендер, загрузка, сам запуск браузера) ловятся и
  превращаются в `status: 'failed'` с `data.pdfArtifact: null`, не бросаются.**
  Это прямое выполнение акцептанса «ошибка PDF не блокирует веб-отчёт» —
  вызывающий код может продолжить, просто не получив PDF-артефакт.
- `context.browser()?.close()` в `finally` — фабрика отдаёт только
  `BrowserContext`, закрытие именно через её `browser()`-аксессор закрывает и
  контекст, и процесс Chromium. Само закрытие — в собственном `try/catch`:
  `close()` отказывает на уже упавшем браузере (типичное состояние сразу после
  сбоя `goto`/`pdf`), а исключение из `finally` заменило бы уже вычисленный
  `StepResult` и улетело бы из шага — то есть сломало бы акцептанс.

## Тесты

### `apps/web/src/lib/__tests__/service-auth.test.ts`
- Совпадающий `x-service-key` → `true`; несовпадающий → `false`;
  отсутствующий заголовок → `false`; `AUDIT_SERVICE_KEY` не задан → `false`
  даже на пустой заголовок (намеренно: открытый `undefined === undefined`
  не должен проходить).

### `apps/worker/src/__tests__/report-pdf.test.ts`
- Успешный путь: статус `ok`, `pdfArtifact` соответствует результату
  `storage.upload`, `artifacts` содержит тот же артефакт, браузер закрыт.
- URL строится как `{baseUrl без хвостового слэша}/internal/report-render/{auditId}`.
- Домен и «Confidential» присутствуют в `footerTemplate`.
- `serviceKey` передаётся в фабрику контекста как есть.
- Нет-ok ответ роута (404), отказ `page.goto`, отказ `page.pdf()`, отказ
  `storage.upload`, отказ самой фабрики контекста, отказ `context.newPage()` —
  во всех случаях `status: 'failed'`, `pdfArtifact: null`, заметка с причиной,
  браузер всё равно закрыт (кроме случая, когда фабрика сама не создала контекст).
- Брошено не-`Error` значение (строка) → ветка `String(err)`, шаг всё равно
  резолвится `failed`.
- Отказ `browser.close()` — шаг не бросает: при успешном PDF остаётся `ok`,
  при предшествующем сбое сохраняется исходная заметка (а не ошибка закрытия).
- `context.browser()` вернул `null` → без падения.
- Домен html-экранируется в `footerTemplate` (кавычка/угловая скобка в домене
  иначе ломала бы футер на каждой странице).

### `apps/worker/src/__tests__/internal-render-factory.test.ts` (добавлен на втором круге ревью)

`createInternalRenderContext` остаётся тонкой обёрткой над Playwright API —
само открытие браузера и навигация по-прежнему проверяются через DI на уровне
шага (`report-pdf.test.ts` инжектирует фабрику целиком). Но валидация
`baseUrl` внутри фабрики (см. «Поправка 2026-10-01» в ADR-025) — чистая логика
до `chromium.launch()`, и её стоило закрепить тестом: `playwright` замокан
(`vi.mock('playwright', ...)`), иначе «браузер не запущен» проверялось бы
случайно — только потому, что браузеры Playwright не установлены в CI, а не
потому, что валидация действительно останавливает выполнение раньше.
Покрывает: непарсибельный `baseUrl`, схемы без протокола
(`new URL('localhost:3000')` не бросает — WHATWG-парсер даёт opaque origin),
не-http(s) схемы, утечку `serviceKey`/креденшелов/query-параметров в текст
ошибки. Блокирующая логика самого гарда (`shouldBlockRequest` и новая
`shouldBlockInternalRequest`) покрыта в `browser-guard.test.ts`, включая
обход через userinfo, регистр, нормализацию порта, непригодный
`allowedOrigin`.

## Проверка вручную

С `DATABASE_URL` и `AUDIT_SERVICE_KEY`, заданными в окружении веба: создать
аудит с `auditType !== 'teaser'`, записать произвольные строки в
`scores`/`findings`/`techChecks`/`mentions`/`engineRuns`/`prompts` вручную,
открыть `/internal/report-render/{auditId}` с заголовком
`x-service-key: $AUDIT_SERVICE_KEY` (`curl`) — ожидается HTML-страница с
версткой `Report_Print.html`; без заголовка или с неверным значением — 404.
Прогон самого шага `generateReportPdf` против живого Chromium — после
появления реального воркер-окружения (нет в CI сегодня, Playwright browsers
не устанавливаются в тестовом прогоне).
