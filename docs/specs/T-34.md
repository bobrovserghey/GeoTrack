# T-34 — Анализ цитируемых страниц конкурентов

## Статус

В разработке

## Зависимости

- T-32 (source map — домены и URL, которые LLM цитируют)
- T-33 (content-check — функции разбора HTML, переиспользуются)

## Зачем

T-33 извлекает C2/C3/C4-факты по страницам **клиента**. T-35 (скоринг столпа C) будет сравнивать клиента с **медианой** страниц, которые LLM реально цитирует по промптам категории. T-34 — шаг сбора этой медианы: берёт топ-N URL из source map (не принадлежащих клиенту), загружает их и извлекает те же C2/C3/C4-факты.

Критерий приёмки из роудмэпа: **«В находке есть ссылка на конкретную цитируемую страницу»** — значит, `CitedPageFact` должен хранить `url` каждой отдельной страницы.

## Вход

```ts
type CitedPagesInput = {
  entityName: string;           // имя клиента для поиска упоминаний
  competitorNames: string[];    // имена конкурентов для поиска упоминаний
  sourceMap: SourceMapOutput;   // из T-32
  maxPages: number;             // из профиля, default 20
};
```

## Выход

```ts
type CitedPageFact = {
  url: string;
  domain: string;
  citedCount: number;
  structure: PageStructureFact;       // C2-измерения (переиспользует тип из T-33)
  stats: PageStatsFact;               // C3-измерения
  freshness: PageFreshnessFact;       // C4-измерения
  mentionsClient: boolean;
  mentionedCompetitors: string[];     // имена конкурентов, найденные в тексте
};

type CitedPagesOutput = {
  analyzedPageCount: number;
  pages: CitedPageFact[];
  // Медианы по всем загруженным страницам:
  medianHasAnswerFirstParagraphRatio: number;   // 0..1
  medianHasListsOrTablesRatio: number;          // 0..1
  medianNumericFactsPer1kWords: number;
  medianAgeDays: number | null;
  pagesWithClientMentionCount: number;
};
```

## Алгоритм

1. **Отобрать URL.** Из `sourceMap.entries` исключить записи с `isClientDomain: true`. Остальные отсортировать по `citedCount` DESC, затем развернуть в список URL (из поля `entry.urls`), дедуплицировать, взять первые `maxPages`.

2. **Загрузить страницы.** Для каждого URL вызвать `deps.getPageData(url)`. Ошибки загрузки — пропустить, добавить `url` в `notes`. Параллельность не требуется — последовательно достаточно.

3. **Извлечь факты для каждой страницы:**
   - **C3 (stats):** вызвать переиспользуемую `computeStatsFact(url, text)` из `content-check.ts`.
   - **C4 (freshness):** вызвать переиспользуемую `extractLastModified(html)` из `content-check.ts`.
   - **Упоминания:** в `text = stripHtml(html)` искать `entityName` (без учёта регистра) → `mentionsClient`; для каждого `competitorNames[i]` — то же → `mentionedCompetitors`.

4. **C2 (structure) — батчевый LLM-вызов.** Собрать все успешно загруженные страницы в один промпт через переиспользуемую `buildStructurePrompt(pages)` из `content-check.ts`. Распарсить через `parseStructureResults`. При ошибке LLM — fallback: все поля `false`.

5. **Сборка `CitedPageFact`.** Для каждой загруженной страницы собрать запись из шагов 3–4. Домен берётся из `sourceMap.entries` (по совпадению `url` через `entry.urls`). `citedCount` — из той же записи.

6. **Медианы.** Вычислить по всем `pages`:
   - `medianHasAnswerFirstParagraphRatio` = (count where `hasAnswerFirstParagraph`) / total
   - `medianHasListsOrTablesRatio` = (count where `hasListsOrTables`) / total
   - `medianNumericFactsPer1kWords` — медиана массива
   - `medianAgeDays` — медиана ненулевых значений, `null` если нет ни одного
   - `pagesWithClientMentionCount` = count where `mentionsClient`

7. **Возврат.** `StepResult<CitedPagesOutput>` со статусом `'ok'` всегда. Пустой `pages: []` допустим (если source map пустой или все загрузки упали).

## Зависимости реализации

Шаг переиспользует из `apps/worker/src/steps/content-check.ts`:
- `stripHtml`
- `computeStatsFact`
- `extractLastModified`
- `buildStructurePrompt`
- `parseStructureResults`

Эти функции **уже экспортируются** из content-check.ts (они нужны тестам), поэтому импорт прямой, без циклических зависимостей.

`ContentCheckDeps` переиспользуется как `CitedPagesDeps` (те же `getPageData` и `model`), плюс `nowMs`.

`PageStructureFact`, `PageStatsFact`, `PageFreshnessFact` — импортируются из `packages/core/src/steps/content-check.ts`.

## Тесты (детерминированное ядро)

1. **Отбор URL:** source map с 3 записями (2 не-клиент, 1 клиент) → взяты только 2 не-клиентские; сортировка по `citedCount`.
2. **Лимит maxPages:** 15 URL на входе, `maxPages=10` → `analyzedPageCount ≤ 10`.
3. **Упоминание клиента:** HTML содержит имя клиента → `mentionsClient: true`.
4. **Упоминание конкурентов:** HTML содержит имя конкурента → в `mentionedCompetitors`.
5. **Медиана numericFacts:** 3 страницы с известными значениями → проверить median.
6. **Медиана ageDays:** 2 страницы с датами, 1 без → медиана по 2 известным.
7. **pagesWithClientMentionCount:** 2 из 3 упоминают клиента → count = 2.
8. **Ошибка загрузки:** `getPageData` кидает → страница пропущена, `analyzedPageCount` не считает её.
9. **Ошибка LLM C2:** `model.generate` кидает → `hasAnswerFirstParagraph: false` для всех (fallback).
10. **Пустой source map:** все записи с `isClientDomain: true` → `pages: []`, `analyzedPageCount: 0`, статус `'ok'`.
11. **Дедупликация URL:** одинаковый URL встречается в двух записях source map → берётся один раз.

## Критерий приёмки

- `pages[i].url` хранит конкретный URL страницы (не домен) — условие для нахождения ссылки в T-41.
- `pagesWithClientMentionCount` корректен на stub-данных.
- 11 тестов зелёные, typecheck чист.
