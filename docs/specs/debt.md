# Технический долг

Сюда агент-исполнитель записывает всё, что сознательно упрощено или отложено внутри задачи. Каждая запись: дата, задача, что упрощено и почему, когда нужно вернуться.

## 2026-09-28, T-78 — ни один адаптер не проверяет причину остановки генерации

Ни `ClaudeAdapter` (`stop_reason`), ни `GeminiAdapter` (`finish_reason`) не проверяют,
была ли генерация модели оборвана по лимиту токенов, — обрезанный ответ сейчас
молча засчитывается как полный. Для `ClaudeAdapter` с `max_tokens: 1024` это не
практический риск: результаты поиска тарифицируются как входные токены,
`cited_text` в цитатах не входит в выход, и реалистичный ответ с одной-двумя
цитатами укладывается в низкие сотни токенов (в фикстуре — 98). Не увеличивать
`MAX_TOKENS` без конкретного случая обрезки — увеличение вдвое только удваивает
потолок стоимости худшего случая, не решая гипотетическую проблему.

Когда возвращаться: если реальные прогоны покажут обрезанные ответы, добавить
проверку `stop_reason === 'max_tokens'` (Claude) / `finish_reason !== 'STOP'`
(Gemini) как общий паттерн для всех адаптеров разом, а не точечно для одного.

## 2026-09-28, T-78 — `claude` отсутствует в enum `engine` схемы БД

`packages/db/src/schema/pipeline.ts` определяет `engineEnum` как
`['perplexity', 'chatgpt', 'gemini']` — без `'claude'`. Это осознанно вне
скоупа T-78 (правило CLAUDE.md: «не менять схему данных внутри задачи про
интерфейс — отдельный PR»). Первая же запись `engine_runs` с движком Claude
упадёт на `invalid input value for enum engine`.

Когда возвращаться: отдельным PR со схемой — миграция
`ALTER TYPE engine ADD VALUE 'claude'` — до того, как `ClaudeAdapter` реально
подключат в пайплайн воркера (часть работы T-29/дальнейшей задачи).

## 2026-09-28, T-78 — тест `engine-poll-standard-profile` не знает про Claude

`apps/worker/src/__tests__/engine-poll-standard-profile.test.ts` жёстко

Тест проходит, но больше не отражает реальный состав профиля `standard`
после этой задачи.

Когда возвращаться: вместе с миграцией enum `engine` и реальным подключением
адаптеров в `apps/worker` — обновить тест до четырёх движков разом.

## 2026-09-28, T-78 — дизайн-бриф ещё говорит «три движка» для Standard

`docs/product/GEOTRACK_DESIGN_BRIEF_ADDENDUM_RU_2026-09-25.md` (строки 68, 149)
описывает тариф Standard как «три движка» — устарело после добавления Claude
четвёртым движком (ADR-024). Не правил сам: это точный текст для страницы
выбора тарифа (правило 1:1), правка — решение продакта, не агента.

Когда возвращаться: продакт обновляет бриф (или явно поручает правку) перед
тем, как страница выбора тарифа верстается или уходит в продакшен.
