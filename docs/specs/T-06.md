# T-06 — Опрос ленты прогресса и токен прогресса

## Scope

- `packages/core/src/progress-token.ts` — `generateProgressToken()`, `hashProgressToken()`
- `packages/core/src/__tests__/progress-token.test.ts` — 9 тестов
- `packages/core/src/index.ts` — экспорт обеих функций
- `apps/web/src/app/api/progress/route.ts` — `GET /api/progress`

## Контракт API

```
GET /api/progress?token=<raw_token>&after_seq=<n>
```

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `token` | обязательный | сырой прогресс-токен (не хэш) |
| `after_seq` | `-1` | вернуть события с seq > этого значения |

Ответ `200`:
```json
{
  "auditId": "<uuid>",
  "status": "<AuditStatus>",
  "isTerminal": false,
  "events": [
    { "seq": 0, "eventType": "status.changed", "payload": {}, "createdAt": "..." }
  ]
}
```

Ошибки: `400` (нет токена), `401` (неверный или просроченный), `404` (аудит удалён).

## Токен прогресса

- Генерируется при создании аудита: `generateProgressToken()` → `{ token, hash }`
- Сохраняется в `report_tokens` с `tokenType='progress'` и `expiresAt = now + 7 дней`
- В базе хранится хэш (sha256 hex), сырой токен остаётся у клиента
- Выдаётся вместе с `auditId` при создании аудита (T-21)

## Протокол клиента

1. Запомнить `lastSeq = -1`
2. Раз в 2 секунды: `GET /api/progress?token=...&after_seq=<lastSeq>`
3. Обновить `lastSeq` до `max(events[*].seq)` если события есть
4. При `isTerminal: true` — остановить опрос

Перезагрузка или обрыв любой длины восстанавливают ленту без пропусков и дублей: клиент передаёт последний известный `seq`, сервер отдаёт строго больше него.

## Acceptance criteria

- `generateProgressToken()` возвращает URL-safe токен ≥ 40 символов и 64-символьный hex хэш ✓
- `hashProgressToken(token)` детерминирован и совпадает с хэшем из `generateProgressToken` ✓
- API возвращает `401` на неверный токен ✓
- API возвращает `401` на просроченный токен ✓
- API возвращает только события с `seq > after_seq`, упорядоченные по seq ✓
- Повторный запрос с тем же `after_seq` не дублирует события ✓ (идемпотентность SELECT)
- `isTerminal: true` при статусах `delivered`, `failed`, `cancelled` ✓
