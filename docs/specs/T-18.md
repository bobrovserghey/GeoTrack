# T-18 — Шаг опроса движков (engine poll step)

## Цель

Реализовать функцию `pollEngines`, которая для каждой пары (промпт, движок):

1. Проверяет кэш категорий — возвращает уже сохранённые повторы.
2. Запрашивает только отсутствующие повторы у адаптера движка.
3. Соблюдает потолки бюджета (мягкий / жёсткий).
4. Соблюдает лимит параллельности на движок.
5. Повторяет запрос при получении ошибок с кодами 429 / 503.

## Входные данные

```ts
type EnginePollInput = {
  prompts: BundledPromptEntry[];
  categoryId: string;
  locale: string;
  promptSetVersion: number;
  promptRepeats: number;   // сколько повторов нужно на каждый промпт
};
```

Бюджет (`Budget`), список адаптеров (`EngineAdapter[]`), реестр движков (`EngineRegistryEntry[]`) и стор кэша (`CacheStore`) передаются отдельно.

## Выходные данные

`StepResult<EnginePollOutput>`:

```ts
type EnginePollOutput = {
  responses: EnginePollResponse[];   // все собранные ответы (кэш + свежие)
  partialEngines: EngineId[];         // движки, у которых хотя бы один повтор провалился
  hardCeilingHit: boolean;            // был ли достигнут жёсткий потолок бюджета
};

type EnginePollResponse = {
  promptId: string;
  engineId: EngineId;
  repeatIndex: number;
  responseText: string;
  sources: { url: string; title?: string }[];
  fromCache: boolean;
  usage: UsageRecord;    // нули для кэшированных ответов
};
```

Статус шага: `'ok'` если все движки ответили без ошибок и без превышения бюджета; `'partial'` иначе.

## Кэш категорий

- Брендовые промпты (`branded: true`): кэш **не читается и не пишется**, движок всегда опрашивается.
- Обычные промпты: читаем все уже сохранённые повторы; запрашиваем только отсутствующие; сохраняем каждый новый ответ.

## Бюджет

Трекер spend (`makeSpendTracker`) работает в оперативной памяти, потокобезопасно в рамках одного вызова `pollEngines`.

- Проверка и запись `spend.record()` происходят **внутри семафора** — это гарантирует корректное поведение при concurrencyLimit=1 (последовательная проверка перед каждым запросом).
- Если `isHardExceeded()` вернул `true` — задача возвращает `SKIPPED` (Symbol), адаптер не вызывается, движок **не добавляется** в `partialEngines`.
- При превышении мягкого потолка в `notes` добавляется предупреждение; опрос продолжается до жёсткого.

## Ретраи

Параметры из `EngineRegistryEntry`: `retryOnStatus: [429, 503]`, `maxRetries`, `timeoutMs`.

Ошибка считается retriable если её `message` содержит код статуса. Задержка между попытками — экспоненциальная (`2^attempt × 1000 мс`), переопределяется через `opts.getRetryDelay`.

Если все попытки исчерпаны — адаптер возвращает `null`, движок добавляется в `partialEngines`.

## Параллельность

Для каждого движка создаётся отдельный семафор с лимитом `concurrencyLimit` из реестра. Все задачи запускаются через `Promise.all`.
