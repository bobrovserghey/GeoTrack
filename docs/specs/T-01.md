# T-01. Монорепозиторий, pnpm workspaces, CI, линтер, правило границ пакетов

Статус: согласовано
Неделя: 1
Источник: GEOTRACK_TECH_PLAN_MVP_RU.md, разделы 3.1–3.4

## Задача

Настроить монорепозиторий с pnpm workspaces так, чтобы пустая сборка проходила
(tsc, lint, tests зелёные в CI) и нарушение границ пакетов ломало CI через ESLint.

## Входы и выходы

Вход: пустой репозиторий со структурой директорий из недели 0.
Выход: все шесть пакетов/приложений типизируются, линтятся и тестируются
из одной команды; CI проходит на чистом pull request.

## Критерий приёмки

- `pnpm lint` проходит на чистом коде; импорт `geotrack-worker` в `packages/core`
  вызывает ошибку `no-restricted-imports`.
- `pnpm typecheck` проходит во всех шести пакетах/приложениях.
- `pnpm test` запускает Vitest и проходит.
- GitHub Actions CI проходит на PR в `main`.
- Прямой импорт `undici` в `apps/worker` вызывает ESLint-ошибку.

## Тесты, которые должны появиться

- `packages/core/src/__tests__/index.test.ts` — тест-заглушка; доказывает,
  что Vitest подхватывает тесты из core.

## Границы

Все корневые конфиги: `package.json`, `pnpm-workspace.yaml`, `tsconfig.base.json`,
`eslint.config.mjs`, `vitest.workspace.ts`, `.github/workflows/ci.yml`.
Каждый пакет: `package.json`, `tsconfig.json`, `src/index.ts`.
apps/web: добавляется минимальный Next.js 15 (layout + page).
apps/worker: минимальный входной файл.

## Что не делаем

Не настраиваем Turborepo. Не делаем production build Next.js в CI (только typecheck).
Не добавляем реальные зависимости в пакеты (кроме next/react в apps/web).
Не пишем тесты границ через ESLint Node API — проверяем вручную при ревью.
