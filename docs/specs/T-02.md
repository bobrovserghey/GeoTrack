# T-02. Схема данных v1, миграции, сиды, проверка Zod/Drizzle

**Зависит от:** T-01  
**Критерий приёмки:** миграции применяются к чистой базе, сид-набор из трёх сайтов загружается

## Таблицы

Все таблицы согласно разделу 4.6 технического плана, сгруппированы по сроку жизни.

### Группа «Аудит и ход работы»

`users`, `audits`, `audit_events`, `orders`, `payments`, `report_tokens`

### Группа «Сайт и продукт»

`sites`, `pages`, `passports`, `categories`, `competitors`

### Группа «Измерения»

`prompts`, `engine_runs`, `mentions`, `tech_checks`, `offsite_signals`, `agent_runs`

### Группа «Результат»

`scores`, `findings`

### Группа «Служебное»

`category_cache`

## Правила схемы (из раздела 4.6)

- Сырые артефакты — в Storage, в базе только ссылка, размер и хэш
- `audit_events` — только лента прогресса, не источник состояния
- `seq` в `audit_events` монотонный в рамках аудита
- Персональные данные: email и domain в `users` + `audits`
- Два поля в каждой таблице измерений: `audit_id` и `step_version`
- Флаг `is_internal` исключает аудит из бенчмарков и лимитов
- Все таблицы с внешним доступом — RLS включён

## Тесты

- `schema-alignment.test.ts`: drizzle-zod и ручные Zod-схемы разбирают одинаковые данные
- `migration.test.ts`: миграции применяются к чистой базе (требует DATABASE_URL, пропускается если нет)
- `seeds.test.ts`: сид-данные разбираются Zod-схемами без ошибок
