# T-17 — Кэш категорий по идентификаторам

## Зависимости

Зависит от T-02 и T-14b (оба смёрджены).

## Цель

Второй сайт той же категории обходится дешевле первого: ответы движков берутся из кэша, а не запрашиваются заново. Брендовые промпты не кэшируются — они персонализированы и не могут переиспользоваться между сайтами.

## Ключ кэша

`(category_id, locale, prompt_set_version, prompt_id, engine_id, repeat_index)`

| Поле | Тип | Описание |
|---|---|---|
| `category_id` | varchar(128) | Идентификатор категории (kebab-case) |
| `locale` | varchar(8) | Локаль промпта (`en`, `ro`) |
| `prompt_set_version` | integer | Версия набора промптов (integer из поля `version`) |
| `prompt_id` | varchar(128) | Идентификатор промпта из набора (kebab-case) |
| `engine_id` | varchar(32) | Идентификатор движка (`perplexity`, `chatgpt`, `gemini`) |
| `repeat_index` | integer | Номер повтора (0-based) |

## Значение

Ответ движка на конкретный промпт с конкретным повтором: `responseText`, `sources`, `usageTokensIn`, `usageTokensOut`.

## TTL

14 дней с момента создания записи (`expires_at`).

## Правила

- **Брендовые промпты (`branded: true`) никогда не кэшируются и не возвращаются из кэша.**
- Попытка сохранить брендовый промпт — тихий no-op.
- Повторы дозапрашиваются: если в кэше есть repeat_index 0 и 1 при requiredCount=3, запрашивается только repeat_index 2.
- Конфликт по уникальному ключу при вставке — игнорируется (`onConflictDoNothing`).

## Схема данных

Таблица `category_cache` (миграция `0001_category_cache_v2.sql`):

| Колонка | Тип | Описание |
|---|---|---|
| `id` | uuid | PK, auto |
| `category_id` | varchar(128) | Ключ: идентификатор категории |
| `locale` | varchar(8) | Ключ: локаль |
| `prompt_set_version` | integer | Ключ: версия набора промптов |
| `prompt_id` | varchar(128) | Ключ: идентификатор промпта |
| `engine` | varchar(32) | Ключ: движок |
| `repeat_index` | integer | Ключ: номер повтора (default 0) |
| `response_text` | text | Текст ответа |
| `sources` | jsonb | Источники |
| `usage_tokens_in` | integer | Входные токены |
| `usage_tokens_out` | integer | Выходные токены |
| `expires_at` | timestamp tz | Срок жизни записи |
| `created_at` | timestamp tz | Метка создания |

Уникальное ограничение: `(category_id, locale, prompt_set_version, prompt_id, engine, repeat_index)`.

## Архитектура модуля

Модуль разбит на два файла:

- `apps/worker/src/cache/category-cache.ts` — чистая бизнес-логика (`CacheLookupKey`, `CacheEntry`, `CacheStore` interface, функции `getCacheEntries`, `getMissingRepeats`, `setCacheEntry`)
- `apps/worker/src/cache/drizzle-cache-store.ts` — реализация `CacheStore` поверх Drizzle

Такое разделение позволяет тестировать бизнес-логику без реального Postgres.

## Тесты

`apps/worker/src/__tests__/category-cache.test.ts` — 20 unit-тестов:

- `getCacheEntries`: miss, hit, содержимое ответа, передача ключа в store
- `setCacheEntry`: кэширование не-бренд промпта, запрет кэширования брендовых, TTL 14 дней, repeat_index в записи, передача ключа
- `getMissingRepeats`: пустой кэш, все есть, частичный кэш, requiredCount=1, requiredCount=0
- Изоляция по locale: запрос с ro-ключом не мешается с en
- Изоляция по prompt_set_version: разные версии — разные ключи
- Брендовый запрет: несколько вызовов с branded=true — нет вставок

## Критерии готовности (acceptance)

- Второй сайт той же категории дешевле первого (ответы берутся из кэша)
- Брендовые промпты не кэшируются
- Повторы дозапрашиваются: недостающие repeat_index добавляются к очереди
- Нет смешения локалей и версий набора промптов
