# T-78: Адаптер Claude — четвёртый движок платных профилей

## Цель

Добавить `ClaudeAdapter`, реализующий `EngineAdapter` (`packages/core/src/contracts/engine.ts`),
как четвёртый движок оценки видимости — наравне с Perplexity, ChatGPT и Gemini,
только в платных профилях (`standard`, `extended`).

## Зависимости

- T-07 — контракт `EngineAdapter` и общий набор контрактных тестов
- ADR-024 — решения по модели, ограничению поиска и тарификации

## Решения (см. ADR-024)

- Модель: `claude-haiku-4-5-20251001` (не флагман — тот же принцип, что для ChatGPT)
- Инструмент `web_search_20250305`, `max_uses: 1` — не более одного поиска за вызов
- Режим без поиска для Claude не используется
- Тарификация по факту (`usage.server_tool_use.web_search_requests`), не жёстко заданной единице
- Только `standard`/`extended`; тизер и аутрич остаются на Perplexity

## Файл 1: `packages/core/src/contracts/engine.ts`

`EngineId` расширен: `'perplexity' | 'chatgpt' | 'gemini' | 'claude'`.

## Файл 2: `packages/core/src/adapters/claude.ts`

`ClaudeAdapter implements EngineAdapter`:
- `id: EngineId = 'claude'`
- `ask()` — `POST https://api.anthropic.com/v1/messages`, заголовки `x-api-key`,
  `anthropic-version: 2023-06-01`; тело: `model`, `max_tokens`, `messages`,
  `tools: [{ type: 'web_search_20250305', name: 'web_search', max_uses: 1 }]`
- Текст ответа — конкатенация всех блоков `type: 'text'`
- Источники — `citations` внутри текстовых блоков, `type: 'web_search_result_location'`,
  дедуплицированные по `url` (тот же принцип, что у `ChatGptAdapter` с `url_citation`)
- `usage.provider = 'anthropic'`, `usage.model = this.model`
- `costUsd` — `calcCallCost('anthropic', model, tokensIn, tokensOut, { webSearchCalls })`,
  где `webSearchCalls = raw.usage?.server_tool_use?.web_search_requests ?? 0`
- HTTP-ошибка → `throw new Error(\`Claude Messages API error: ${res.status}\`)`

## Файл 3: `packages/config`

- `engines.v1.json` — запись `claude` (провайдер `anthropic`, модель
  `claude-haiku-4-5-20251001`, `concurrencyLimit: 5`, `retryOnStatus: [429, 503]`)
- `schemas/engine-registry.ts` — `id: z.enum([..., 'claude'])`
- `provider-prices.v1.json` — `anthropic/claude-haiku-4-5-20251001`:
  `inputPerMToken: 1.0`, `outputPerMToken: 5.0`, `webSearchCallPer1k: 10.0`
- `audit-profiles.v2.json` — `claude` добавлен в `engines` для `standard` и
  `extended`; `costSoftCeilingPerAdditionalLocaleUsd`/`costHardCeilingPerAdditionalLocaleUsd`
  для `extended` подняты с 3.00/4.00 до **4.00/5.00** (юнит-экономика v1.4, §3.3)
- `schemas/audit-profile-v2.ts` — `EngineIdSchema` расширен значением `'claude'`

## Тесты

### `packages/core/src/__tests__/adapters.claude.test.ts`

Общий контрактный набор (id, непустой text, sources с валидными URL, usage
provider/model, costUsd > 0, raw сохранён, throws на HTTP-ошибке) плюс:
- `max_uses: 1` присутствует в теле запроса для инструмента `web_search`
- `usage.server_tool_use.web_search_requests` из фикстуры ≤ 1
- ответ без обращения к поиску (нет `server_tool_use`/`web_search_tool_result`)
  не тарифицируется как поиск — `costUsd` равен `calcCallCost(..., {})` без
  `webSearchCalls`, посчитанному напрямую в тесте
- дедупликация источников по `url`

### `packages/config`

- `profiles-v2.test.ts` — `standard`/`extended` содержат `'claude'` в `engines`;
  `extended` surcharge 4.0/5.0
- `engines.test.ts` — реестр содержит `claude`

## Что осталось

- Реальное подключение `ClaudeAdapter` в пайплайн (`apps/worker`) — шаг
  `engines.poll` уже принимает адаптеры как DI-параметр, но нигде в воркере
  сейчас не создаются экземпляры ни одного из четырёх адаптеров с реальным
  `apiKey`; это выходит за рамки T-78 (относится к T-29, которая явно зависит
  от T-78).
- Замер расхождения Haiku 4.5 vs более крупная модель — неделя 5, отдельный ADR.
