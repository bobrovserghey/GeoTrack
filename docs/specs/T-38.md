# T-38 — Столп E: машиночитаемые данные (E4) и манифесты агентов (E5)

## Статус

В разработке

## Зависимости

- T-08c (краулер — предоставляет `keyPages` со структурированным списком страниц)

## Зачем

Шаг `collectMachineReadableCheck` собирает факты для двух критериев столпа E:

- **E4 — Машиночитаемые данные (20 баллов)**: страница цен в структурированном виде, публичная документация API, OpenAPI-спецификация, фид продуктов/каталог
- **E5 — Интерфейсы для агентов (15 баллов)**: `llms.txt`, `agents.json`, WebMCP-манифест, MCP-сервер

Scoring (E4 + E5) добавляется в T-40. T-38 собирает только факты.

type MachineReadableCheckInput = {

## Алгоритм E4

### Страница цен (`pricingPageFound`, `pricingStructured`)

1. Найти в `keyPages` URL, pathname которого содержит `/pricing`, `/plans`, `/price`, `/subscribe`.
2. `pricingPageFound = true` если URL найден.
3. Если найден — загрузить страницу через `fetchFn`. При ошибке загрузки: `pricingStructured = false`.
4. `pricingStructured = true` если тело HTML содержит хотя бы одно из:
   - `<script type="application/ld+json">` с `"@type"` равным `"Offer"`, `"PriceSpecification"` или `"Product"`
   - `itemprop="price"` (Schema.org microdata)
   - тег `<table` (эвристика для ценовых таблиц)

### OpenAPI спецификация (`openApiSpecFound`, `openApiSpecUrl`)

Последовательно проверить пути: `/openapi.json`, `/openapi.yaml`, `/swagger.json`, `/.well-known/openapi.json`.  
Первый с `res.ok` и телом (≥ 10 символов) → `openApiSpecFound = true`, `openApiSpecUrl` = URL.

### Документация API (`apiDocsFound`, `apiDocsUrl`)

1. Сначала поискать в `keyPages` URL с pathname `/docs`, `/api-docs`, `/swagger`, `/redoc`, `/api/docs`.
2. Если не найдено, последовательно проверить `fetchFn` на `/docs`, `/api-docs`, `/swagger`, `/redoc`.
3. Первый 200 → `apiDocsFound = true`, `apiDocsUrl` = URL.

### Каталог/фид продуктов (`productCatalogFound`, `productCatalogUrl`)

Последовательно: `/feed.xml`, `/rss.xml`, `/atom.xml`, `/catalog.json`, `/products.json`.  
Первый `res.ok` с телом содержащим `<rss`, `<feed`, `<channel` или валидный JSON-массив → `productCatalogFound = true`.

**E4 всегда `measured: true`** — наличие ценового URL определяется по keyPages без сети; проверки через `fetchFn` при ошибке дают `false`, но не делают шаг неизмеренным.

## Алгоритм E5

| Сигнал | Путь | Условие |
|---|---|---|
| `llmsTxtFound` | `{origin}/llms.txt` | `res.ok` |
| `llmsTxtValid` | то же | `res.ok` && `body.trim().length > 0` |
| `agentsJsonFound` | `{origin}/agents.json` → `{origin}/.well-known/agents.json` | первый `res.ok` |
| `agentsJsonUrl` | первый успешный URL | — |
| `webMcpManifestFound` | `{origin}/.well-known/webmcp-manifest.json` | `res.ok` |
| `mcpServerFound` | `{origin}/.well-known/mcp.json` | `res.ok` |

При исключении в `fetchFn` для каждого пути: сигнал считается `false`.  
**E5 всегда `measured: true`** — отсутствие файлов является валидным измеримым результатом.

## Статус StepResult

Всегда `'ok'` — E4 и E5 всегда измеримы.

## Тесты

### E4 (8 тестов)

1. Pricing URL в keyPages + fetch возвращает JSON-LD с Offer → `pricingStructured: true`
2. Pricing URL в keyPages + fetch возвращает plain HTML без разметки → `pricingStructured: false`
3. OpenAPI spec найден по `/openapi.json`
4. OpenAPI spec — первый путь 404, второй 200 → `openApiSpecUrl` = `/swagger.json`
5. API docs URL найден в keyPages → `apiDocsUrl` из keyPages
6. API docs не в keyPages, `/docs` возвращает 200 → найден
7. Product catalog найден по `/feed.xml` (с тегом `<rss`)
8. Ничего не найдено → все false, `measured: true`

### E5 (6 тестов)

9. `llms.txt` найден с непустым контентом → `llmsTxtFound: true`, `llmsTxtValid: true`
10. `llms.txt` возвращает 200, но пустое тело → `llmsTxtValid: false`
11. `agents.json` не найден по основному пути, найден по `/.well-known/agents.json`
12. `webmcp-manifest.json` найден
13. `mcp.json` найден
14. Все пути возвращают 404 → все false, `measured: true`

### Интеграционный (1 тест)

15. E4 и E5 оба measured → `status: 'ok'`
