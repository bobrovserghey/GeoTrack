# T-30 — Критерий A5: точность описания продукта

## Контекст

**A5** (из методологии): «Совпадает ли описание продукта, цен и функций в ответах движков с сайтом».
Источник правды — «паспорт продукта» из шага `product.passport` (T-08).

Максимальный балл: **15**. Критерий не влияет на G1 (тизер), но необходим для G2 (стандартный профиль).

Если A5 фиксирует неверную цену или несуществующую функцию в >30% ответов — находка помечается критической.

## Зависимости

T-19 (`EngineResponseFacts`, список ответов с `brandMentioned`)

## Scope

### 1. Типы (`packages/core/src/steps/accuracy-check.ts`)
- `AccuracyFact` — результат проверки одного ответа
- `AccuracyCheckOutput` — все факты + `accuracyRate`
- Экспорт через `packages/core/src/index.ts`

### 2. Шаг (`apps/worker/src/steps/accuracy-check.ts`)
- Функция `checkAccuracy(responses, facts, passport, model)`
- Фильтрует ответы, где `brandMentioned = true`
- Строит промпт: паспорт + текст ответа → JSON `{accurate, inaccurate, unverifiable}`
- `responseAccurate` = `inaccurateClaims === 0`
- При ошибке парсинга — `partial`

### 3. Скоринг (`packages/core/src/scoring/pillar-a.ts`)
- Функция `scoreA5(facts: AccuracyFact[], maxScore: number)`
- Обновлённая сигнатура `scorePillarA(..., accuracyFacts: AccuracyFact[] = [])`
- Если `accuracyFacts` пуст → `a5: { measured: false }`

### 4. Тесты (`apps/worker/src/__tests__/accuracy-check.test.ts`)
Unit-тесты для `checkAccuracy`: все точные, часть неточных, нет упоминаний бренда, ошибка модели.

### 5. Тесты скоринга (`packages/core/src/__tests__/scoring-a.test.ts`)
Новые тесты для `scoreA5` и интеграция с `scorePillarA`.

### 6. Золотой набор (`fixtures/golden/accuracy/set-v1.json`)
50 размеченных примеров: текст ответа + паспорт + метка `accurate` / `inaccurate`.

### 7. Eval-харнесс (`apps/worker/src/evals/accuracy-check.eval.ts`)
- Читает `set-v1.json`, гоняет каждый пример через модель
- Считает accuracy vs. метки
- Порог: ≥ 0,85 на 50 примерах
- Запускается через `pnpm test:eval`; пропускается если нет `GEMINI_API_KEY`

### 8. `package.json`
Добавить скрипт `test:eval`.

## Acceptance criteria

1. `checkAccuracy` возвращает `AccuracyFact[]` с корректными счётчиками.
2. `scoreA5([], maxScore)` → `measured: false`.
3. `scorePillarA` с пустым `accuracyFacts` → `a5.measured === false` (обратная совместимость).
4. `scorePillarA` с непустым `accuracyFacts` → `a5.measured === true`, балл > 0 если точность > 0.
5. Eval-скрипт читает `set-v1.json` и сообщает accuracy; при порогe < 0,85 выходит с кодом 1.
6. `pnpm test` зелёный.
