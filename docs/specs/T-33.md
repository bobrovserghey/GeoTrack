# T-33 — Контент-анализ C1–C6 на десяти страницах

Статус: согласовано
Неделя: 6
Источник: GEOTRACK_AUDIT_METHODOLOGY_RU.md §2.3 (столп C); GEOTRACK_TECH_PLAN_MVP_RU.md §7.2 (`content.analyze`), §13.2

## Задача

Для до десяти ключевых страниц клиентского сайта извлечь факты по критериям
C1–C6. Шаг принимает список URL и паспорт продукта; загружает каждую страницу
через инжектируемую функцию; возвращает `ContentCheckFacts` — структурированные
измерения для последующего скоринга в T-35 и сравнения с цитируемыми страницами
в T-34.

Acceptance: шаг возвращает баллы и артефакты на пяти эталонных сайтах; eval
точности LLM-критериев (C2, C5) ≥ 0,82 macro-F1.

## Методология критериев

| Критерий | Вес | Метод реализации |
|---|---|---|
| C1. Покрытие intent-страниц | 25 | Детерминированный: паттерны URL + title/H1 |
| C2. Структура «ответ сначала» | 20 | LLM: анализ структуры страниц |
| C3. Статистика, цитаты, источники | 20 | Эвристика: regex-подсчёт |
| C4. Свежесть контента | 15 | Детерминированный: извлечение дат |
| C5. Ясность сущности | 10 | LLM: первые 100 слов главной страницы |
| C6. URL и заголовки | 10 | Детерминированный: паттерны URL/title |

## Входы и выходы

```ts
// packages/core/src/steps/content-check.ts

/** Intent page types T-33 looks for */
export type IntentType = 'pricing' | 'comparison' | 'alternatives' | 'use-cases' | 'docs' | 'faq';

export type IntentPageMap = Record<IntentType, string | null>; // intent → URL or null

export type PageStructureFact = {
  url: string;
  hasAnswerFirstParagraph: boolean;  // LLM
  hasQuestionHeaders: boolean;        // LLM
  hasQABlocks: boolean;               // LLM
  hasListsOrTables: boolean;          // regex
};

export type PageStatsFact = {
  url: string;
  wordCount: number;
  numericFactsPer1kWords: number;      // numbers, percentages, multipliers
  citationPatternsPer1kWords: number;  // [1], (Author YYYY), footnote-style
};

export type PageFreshnessFact = {
  url: string;
  lastModified: string | null;  // ISO date (YYYY-MM-DD) extracted from meta/schema/visible
  ageDays: number | null;       // computed relative to audit date
};

export type PageUrlFact = {
  url: string;
  title: string;
  h1: string;
  urlReadable: boolean;  // no hex IDs, no random strings, path segments are words
};

export type EntityClarityFact = {
  entityMentioned: boolean;           // LLM
  categoryMentioned: boolean;         // LLM
  targetAudienceMentioned: boolean;   // LLM
  testedText: string;                 // first ≤100 words used for the check
};

export type ContentCheckFacts = {
  analyzedPageCount: number;
  c1: {
    pageTypeMap: IntentPageMap;
    gapTypes: IntentType[];  // intent types with no matching page found
  };
  c2: {
    pages: PageStructureFact[];
  };
  c3: {
    pages: PageStatsFact[];
    medianNumericFactsPer1kWords: number;
  };
  c4: {
    pages: PageFreshnessFact[];
    medianAgeDays: number | null;
  };
  c5: EntityClarityFact;
  c6: {
    pages: PageUrlFact[];
    readableUrlRatio: number;  // 0.0–1.0
  };
};
```

## Алгоритм analyzeContent

**Вход:**
```ts
type ContentCheckInput = {
  domain: string;
  entityName: string;       // из PassportOutput
  categoryLabel: string;    // человекочитаемый ярлык категории
  keyPages: string[];       // до 10 URL (первый — главная страница)
};
```

**Зависимости:**
```ts
type GetPageDataFn = (url: string) => Promise<{ html: string }>;

type ContentCheckDeps = {
  getPageData: GetPageDataFn;
  model: ModelAdapter;
  nowMs?: number;  // инжектируется для тестов
};
```

**Поведение:**

1. **Загрузка**: для каждого URL вызвать `getPageData` → получить HTML. Ошибку
   одной страницы логировать и пропустить (частичный результат допустим).

2. **C1 — Intent coverage** (детерминированный):
   Для каждого типа intent сопоставить URL + title + H1 с паттернами:
   - `pricing`: `/pricing`, `/plans`, `/tariff`, title/H1 содержит «pric» или «plan»
   - `comparison`: `/vs/`, URL содержит «-vs-», title содержит «vs » или «comparison»
   - `alternatives`: URL/title содержит «alternativ»
   - `use-cases`: URL/title содержит «use-case», «use case», «solution»
   - `docs`: URL содержит `/docs`, `/documentation`, `/help`, `/support`
   - `faq`: URL/title содержит «faq», «frequently asked»

3. **C2 — Answer-first structure** (LLM, одним вызовом для всех страниц):
   Для каждой страницы извлечь stripped text (первые 2000 слов), заголовки и
   первый абзац. Отправить в LLM одним запросом, получить JSON-массив.
   `hasListsOrTables` определяется regex по сырому HTML (`<ul`, `<ol`, `<table`).

4. **C3 — Stats density** (эвристика, детерминированная):
   На stripped text:
   - numericFacts: числа, проценты (`\d+\.?\d*\s*%`), множители (`\d+[xX]`)
   - citationPatterns: `\[\d+\]`, `\(\w+,?\s+\d{4}\)`, `\[\w+\s+\d{4}\]`
   Делить на число слов / 1000.

5. **C4 — Freshness** (детерминированный):
   Извлечь дату из HTML в порядке приоритета:
   a. JSON-LD `dateModified` или `datePublished`
   b. `<meta property="article:modified_time">`
   c. `<meta name="last-modified">`
   d. Видимый паттерн вида «Updated [Month] [YYYY]», «Last updated [date]»
   `ageDays = (nowMs - Date.parse(found)) / 86_400_000`, округлить до целого.

6. **C5 — Entity clarity** (LLM, один вызов):
   Извлечь первые 100 слов главной страницы (первый URL в `keyPages`).
   Отправить в LLM с контекстом: entityName, categoryLabel.
   Ожидаемый ответ: `{"entityMentioned":bool,"categoryMentioned":bool,"targetAudienceMentioned":bool}`.

7. **C6 — URL/title quality** (детерминированный):
   URL читаем, если все path-сегменты состоят из слов/дефисов (нет UUID, нет
   `[0-9]{4,}`, нет hex-последовательностей `[0-9a-f]{8,}`).
   `title` и `h1` извлекаются из HTML regex-ом.

8. Собрать `ContentCheckFacts` и вернуть `StepResult<ContentCheckFacts>` со
   `status: 'ok'`.

## LLM-промпты

### C2 — структурный анализ (batched)

```
You are a content structure analyzer.

For each page below, analyze the content and return a JSON array.
Each item: {"url":"...","hasAnswerFirstParagraph":bool,"hasQuestionHeaders":bool,"hasQABlocks":bool}

Rules:
- hasAnswerFirstParagraph: the first paragraph directly answers the main heading question
- hasQuestionHeaders: at least one H2 or H3 is phrased as a question (ends with ?)
- hasQABlocks: there is a visible FAQ or Q&A section

Pages:
<per-page: URL + first 2000 words + first heading + first paragraph>

Return JSON array only.
```

### C5 — ясность сущности

```
You are checking whether a homepage clearly communicates what the product is.

Product name: {entityName}
Category: {categoryLabel}

First 100 words of homepage:
"{text}"

Return JSON only: {"entityMentioned":bool,"categoryMentioned":bool,"targetAudienceMentioned":bool}
- entityMentioned: the product/brand name appears in these 100 words
- categoryMentioned: the product category or main use case is mentioned
- targetAudienceMentioned: the target audience (who this is for) is mentioned
```
