# T-14b — Генератор брендовых промптов, сборка набора по профилю

## Цель

Реализовать детерминированную функцию `generatePromptBundle`, которая собирает финальный набор промптов для аудита:
- Берёт канонические категорийные промпты из T-14a (по приоритету)
- Генерирует брендовые промпты под конкретный бренд и конкурентов
- Возвращает единый список с флагом `branded` на брендовых промптах

## Входные данные

```ts
{
  brandName: string;       // "Acme CRM"
  categoryId: string;      // "crm-software"
  locale: 'en' | 'ro';
  competitors: string[];   // ["Salesforce", "HubSpot", ...]
  profileId: 'teaser' | 'standard' | 'extended';
}
```

## Выходные данные — `PromptBundle`

```ts
{
  brandName: string;
  categoryId: string;
  locale: 'en' | 'ro';
  profileId: string;
  generatedAt: string;     // ISO date
  prompts: BundledPromptEntry[];
}
```

Каждый `BundledPromptEntry`:
```ts
{
  id: string;              // kebab-case, уникальный в пределах bundle
  text: string;
  type: PromptType | 'brand';
  priority: number;        // 1..N, без пропусков
  branded: boolean;        // true только для брендовых
}
```

## Профильные квоты (жёстко закодированы по profile.id)

| Профиль  | Всего | Категорийных | Брендовых |
|----------|-------|--------------|-----------|
| teaser   | 12    | 10           | 2         |
| standard | 30    | 26           | 4         |
| extended | 50    | 40           | 10        |

## Брендовые промпты (по приоритету)

### English (locale='en')
1. `what is {Brand}`
2. `{Brand} pricing`
3. `{Brand} alternatives`
4. `{Brand} reviews`
5+ `{Brand} vs {Competitor}` — по одному на каждого конкурента из входного списка

### Romanian (locale='ro')
1. `ce este {Brand}`
2. `prețuri {Brand}`
3. `alternative la {Brand}`
4. `recenzii {Brand}`
5+ `{Brand} vs {Competitor}` — универсально

Берём первые `brandCount` доступных брендовых промптов. Если конкурентов не хватает для полного заполнения квоты — берём сколько есть (total < profiled count только при нехватке). В тестах всегда передаём достаточное число конкурентов.

## ID промптов

- Категорийные: сохраняются как в canonical set (`discovery-01`, `problem-01`, ...)
- Брендовые: `brand-01`, `brand-02`, ..., `brand-N`

## Инварианты

- `branded: false` для всех категорийных промптов
- `branded: true` для всех брендовых промптов  
- Приоритеты: непрерывный ряд 1..len(prompts)
- Категорийные всегда идут первыми (по оригинальному priority), брендовые — после
- Брендовые промпты **никогда не кешируются** (флаг используется воркером для пропуска кеша)

## Зависимости

- T-12 (CategoryDetectOutput — предоставляет categoryId)
- T-13 (CompetitorDetectOutput — предоставляет список competitors)
- T-14a (canonical prompt sets — предоставляет категорийные промпты)

## Приёмочные критерии

- [ ] `generatePromptBundle` возвращает ровно 12, 30 или 50 промптов по профилю (при достаточном числе конкурентов)
- [ ] Брендовые помечены `branded: true`, категорийные — `branded: false`
- [ ] `type === 'brand'` у всех брендовых промптов
- [ ] Приоритеты — сплошной ряд без пропусков
- [ ] Категорийные промпты отсортированы по оригинальному приоритету из canonical set
- [ ] Romanian locale генерирует брендовые тексты на румынском
- [ ] ID уникальны внутри bundle
- [ ] Zod-схема `PromptBundleSchema` успешно валидирует результат
