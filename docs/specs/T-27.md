## Адаптер

### Конфигурация из реестра

Реестр (`engines.v1.json`) уже содержит:
```json
{
  "id": "chatgpt",
  "provider": "openai",
  "model": "gpt-4o-mini",
  "concurrencyLimit": 5,
  "retryOnStatus": [429, 503],
  "maxRetries": 4,
  "timeoutMs": 30000
}
```

Адаптер использует модель `gpt-4o-mini-search-preview` (версия для Responses API с веб-поиском) — именно она присутствует в таблице цен `provider-prices.v1.json`. Конфигурационное поле `model` в реестре служит алиасом; адаптер маппит его на нужную модель API либо принимает `model` в опциях конструктора.

### API

- **Endpoint:** `POST https://api.openai.com/v1/responses`
- **Auth:** `Authorization: Bearer {apiKey}`
- **Body:**
  ```json
  {
    "model": "gpt-4o-mini-search-preview",
    "input": "<prompt>",
    "tools": [{ "type": "web_search_preview" }]
  }
  ```
- **Response (успех):**
  ```json
  {
    "output": [
      { "type": "web_search_call", "status": "completed" },
      {
        "type": "message",
        "content": [
          {
            "type": "output_text",
            "text": "Ответ...",
            "annotations": [
              { "type": "url_citation", "url": "https://...", "title": "Страница", "start_index": 0, "end_index": 5 }
            ]
          }
        ]
      }
    ],
    "usage": { "input_tokens": 120, "output_tokens": 80 }
  }
  ```

### Извлечение данных

- `text` — `output[].content[].text` для элементов типа `output_text` первого элемента типа `message`
- `sources` — дедуплицированный список `{ url, title }` из `annotations[].type === 'url_citation'` того же текстового блока
- `usage` — `response.usage.input_tokens` и `response.usage.output_tokens`

### Стоимость

```ts
calcCallCost('openai', 'gpt-4o-mini-search-preview', tokensIn, tokensOut, { webSearchCalls: 1 })
```

Одна веб-поисковая операция = одна единица `webSearchCalls`.

### Класс

```ts
type ChatGptOptions = {
  apiKey: string;
  model?: string;
  fetch?: typeof globalThis.fetch;
};

class ChatGptAdapter implements EngineAdapter {
  readonly id: EngineId = 'chatgpt';
  // ...
  async ask(prompt: string, opts: AskOptions): Promise<EngineAnswer>
}
```

## Фикстура

`fixtures/engines/chatgpt/ask-basic.json` — тело HTTP-ответа (JSON) одного реального вызова Responses API. Записывается командой `pnpm fixtures:record` или вручную. Формат:

```json
{
  "output": [...],
  "usage": { "input_tokens": ..., "output_tokens": ... }
}
```

Файл коммитится в репозиторий и используется тестами вместо сети.

## Тесты (`adapters.chatgpt.test.ts`)

Контрактный набор на фикстуре (fetch инжектируется, сеть не вызывается):

| Тест | Ожидание |
|---|---|
| `adapter.id === 'chatgpt'` | true |
| `ask()` возвращает непустой `text` | `text.length > 0` |
| `sources` — массив объектов `{ url }` | каждый `url` парсится как URL |
| `usage.provider === 'openai'` | true |
| `usage.model === 'gpt-4o-mini-search-preview'` | true |
| `usage.costUsd > 0` | true |
| HTTP 4xx/5xx бросает ошибку с кодом | `error.message` содержит статус |
| Сеть не вызывается из тестов | fetch инжектируется, globalThis.fetch не задействован |

## Что не делаем в T-27

- Обновление модели в `engines.v1.json` — отдельный ADR при смене модели
- Поддержка streaming — не нужна MVP
- Учёт квот и rate-limit backoff — уже задан в реестре (`retryOnStatus`, `maxRetries`)
- Модель-адаптер (GeminiModelAdapter) для ChatGPT — не в скоупе

---

## Критерии приёмки

1. `ChatGptAdapter.id === 'chatgpt'`
2. `ask()` возвращает `EngineAnswer` с непустым `text`
3. `sources` — массив `{ url, title? }` с валидными URL
4. `usage.costUsd > 0` и соответствует тарифу
5. HTTP 4xx/5xx бросает ошибку с кодом
6. Сеть не вызывается из тестов (fetch инжектируется)
7. Все тесты `adapters.chatgpt.test.ts` зелёные
8. `ChatGptAdapter` экспортируется из `packages/core`
